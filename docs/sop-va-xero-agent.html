1. What the agent does

The Xero Agent (“Intactix”) is an autonomous accounting assistant for Intactix B.V., the GoPure EU entity. It keeps a local copy of the Xero ledger in sync, reconciles it against PrestaShop orders and bank/payment feeds, and surfaces the exceptions a human has to decide on.

Entity

Intactix B.V. (GoPure EU) — Xero + NL Belastingdienst VAT

Core job

Reconcile Xero sales invoices ↔ PrestaShop orders; match supplier bills ↔ bank spend ↔ Xero inbox receipts; produce quarterly VAT inputs

Data it reads

Xero API, PrestaShop GP EU (read-only BI replica), Wise, Revolut, Xero Inbox files

Write posture

WRITES ENABLED — but draft-first, always. It creates drafts; a human posts them in Xero. See section 5.

What is worth training it on

Follow the training loop on the OpenClaw page. For this agent, the high-value material is:

  • Supplier behaviour — “when Paulo invoices in USD but we pay in EUR from Wise, subtract the card fee and book the net”

  • Bad matches — point at the reference, ask why it matched, then give the rule that would have prevented it

  • Its decision queue — when it can’t decide, it logs the item, the candidates and what’s missing. Answering those is safe, legitimate VA work: you are supplying facts, not posting to Xero.

What you can actually run. Reading, editing, git and type-checking (npx tsc --noEmit) all work. But src/config.ts validates the environment the moment it is imported and requires MYSQL_PASSWORD and PS_BI_PASSWORD, so anything that executes — the MCP server, the sync scripts, most tests — throws a validation error without .env. Write and type-check your change, then ask the admin to run it. (A scoped .env for VAs is on the open items list.)

5. Xero writes and approvals

Xero writes are LIVE. The agent can create draft invoices, create bills, attach documents and modify contacts in the real Xero organisation, and it will do so if you ask. Nothing in the software stops a VA from triggering a write.

On top of the generic propose-don’t-apply rule, this agent has hard red lines written into its own instructions:

  • Every write tool is run with dry_run=true first, and the dry run shown to a human, before anything real happens. Say “show me the dry run”.

  • Everything it creates in Xero is a DRAFT. It will never post, approve or authorise an invoice or a bill. A human does that in Xero.

  • Say “propose only, do not apply” and it holds for the rest of the session — it will refuse applying tools and tell you what it would have applied instead.

  • It is instructed to assume anyone in #accounting or the Telegram topic may be a VA without approval authority, and to ask for confirmation rather than apply.

  • It will never run SQL that modifies data.

Never ask it to apply proposals, post or approve invoices, or flip a rule live. That is the admin’s call.

6. What it can and can’t do

CAN

Sync & query

Pull Xero, PrestaShop, Wise and Revolut data into its local warehouse; run read-only SQL across all of it; check how fresh the data is

Reconcile

Run a full period reconciliation, match Xero sales invoices to PS orders, list orphans and exceptions, explain why a given item didn’t match

Investigate

Trace a bank line to a supplier bill to a receipt; find the PS order behind a Xero reference; spot missing supplier receipts; audit the Xero inbox

Draft

Create draft sales invoices from PS orphans, create bills from inbox files, attach PDFs to invoices — dry run first, every time

Learn

Propose coding rules, test a rule against history before it’s trusted, build supplier profiles, backtest the invoice builder

Report

Produce NL quarterly VAT inputs, audit VAT rates by country, export unmatched transactions to Excel

CANNOT

Post or approve anything

Everything it creates is a draft. A human posts it in Xero. It has no authorisation rights.

Reconcile bank lines in Xero

It has read-only access to bank transactions. Matching in the Xero bank feed is done by a human.

Move money

It has no payment or transfer tool at all — its Wise and Revolut tools only fetch activity into the warehouse. There is nothing to ask it for.

Change PrestaShop

Its PrestaShop tools only read (the BI replica and order lookups), and it refuses SQL that modifies data. It cannot edit an order.

Invent an FX rate

GBP orders are always flagged for a human to confirm the EUR amount. It will not guess.

Guess a tax treatment

If a ship-to country isn’t in its verified country→tax-type map, it stops and asks. By design.

File the VAT return

It produces the inputs. A human files with the Belastingdienst.

7. Escalate to admin when

The generic list is on the OpenClaw page. On top of it, for this agent:

  • A Xero write needs to actually happen — posting, approving, applying proposals
  • A number doesn’t reconcile against Xero and you can’t explain the gap
  • A sync reports a Xero scope or token error
  • Anything touching the live PrestaShop database or /var/www/
